# 斑马放映室

一个纯静态的卡通风格视频站。卡片像**抓在手里的一叠扑克牌**扇形摊开：
停在哪张，哪张就抽出来、扶正、放大，两边的牌顺着弧线让开一点；
点一下进去，再点一下就开播。无构建、无依赖，丢到 GitHub Pages 就能跑。

内容来自网盘里 `斑马百科/0~4岁热学榜`：10 个目录 × 12 集 = 120 个视频，
片名和缩略图都是从网盘抓下来后存在本地的。

---

## 文件结构

```
index.html                页面骨架
assets/
  css/style.css           全部样式
  js/data.js              ★ 内容清单（由 tools/build_data.py 生成）
  js/app.js               交互逻辑 + 扇形几何
  covers/cover-*.jpg      10 个目录的卡通封面
  thumbs/c00_001.jpg …    120 张视频缩略图（网盘默认缩略图，已裁黑边压成 16:9）
  audio/welcome.mp3       开屏欢迎语（女声，目录页首次加载放一次）
tools/
  pan_sync.py             从网盘拉清单 + 缩略图（本地跑，不进仓库）
  fit_thumbs.py           把缩略图去黑边、裁成 16:9、压到 640×360
  build_data.py           用清单生成 data.js，保留原有封面/主色
```

## 内容是怎么来的

网盘不支持跨域直读，所以走的是「本地同步一次，产出静态文件」这条路：

```bash
python tools/pan_sync.py            # 读网盘目录 → 下载缩略图 → .pan_manifest.json
python tools/fit_thumbs.py          # 去黑边 + 裁 16:9 + 压缩
python tools/build_data.py          # 生成 assets/js/data.js
```

加了新片子、换了目录，重跑这三条就行，页面不用改。

`pan_sync.py` 的登录凭据从本机已有的网盘配置读（脚本里写的是路径），
不写进本仓库；`tools/` 和 `.pan_manifest.json` 已在 `.gitignore` 里。

### 一个视频条目的结构

```js
{
  title: "恐龙的外表",                    // 片名（自动去掉开头的序号）
  ep: 3,                                  // 第几集，显示在牌角
  size: "328.8 MB",                       // 文件大小
  thumb: "assets/thumbs/c01_003.jpg",     // 网盘缩略图
  netdisk: "https://pan.baidu.com/pfile/video?path=…",   // path 必须百分号编码
  path: "/斑马百科/0~4岁热学榜/02恐龙/3.恐龙的外表.mp4"
}
```

## 扇形是怎么排的

`app.js` 里把每张牌当成绕屏幕下方「手心」旋转的一张牌：

```
第 i 张的角度  a = (i - 中位) × 每张角度
位置           x = R · sin(a)      y = R · (1 - cos(a))
```

- `R` 由容器宽度反推，保证整把牌刚好塞进一屏；
- **宽度里提前预留了「让开」的角度**，否则一停到最外侧，牌就顶出屏幕；
- 停住的那张往上抽出 0.44 倍卡高、放大 1.05，其余整半边各让一个角度
  —— 这个角度**按像素等价换算**，窄屏上 3.2° 只有二十几像素，等于没让开；
- 一屏张数按可用宽度分档：手机 4、竖屏平板 5、横屏平板 6~7、桌面 10。

想改手感就动 `app.js` 里的 `maxAngle`、`0.34`（让开幅度）、`0.44`（抽出高度）、`1.05`（放大倍数）。

## 平板适配

| 尺寸 | 张数/屏 | 处理 |
|---|---|---|
| 390 手机 | 4 | 搜索框收成圆形按钮，点开才展开 |
| 768 竖屏 | 5 | 标题区收紧，牌放大到 236px |
| 1024 竖屏 | 5 | 同上 |
| 1024 横屏 | 7 | 翻页箭头放大到 52px，触摸目标够大 |
| 1366+ / 桌面 | 10 | 原样 |

平板竖屏屏幕很高、宽度有限，一张牌能占的横向空间就那么多，
所以那边不追求「牌更大」，而是**少放几张**，保证每张都露得出来。

## ⚠ 播放是怎么走的

网盘分享页不能直接喂给 `<video>`，网盘也没有可公开热链的 mp4。
所以现在点视频卡片的逻辑是：

- 条目**有 `src`** → 站内播放器直接播（直链 / 对象存储 / 自建转存），打开即全屏；
- 条目**只有 `netdisk`** → 站内先出一个「影院页」（全屏、大海报、中间一个播放键），
  点一下才用新标签打开百度网盘自己的播放器（跳 `path`）。多一步点击，是为了让「打开就全屏」成立
  —— 网盘那页归百度管，网页没法命令它全屏。

把直链批量填进 `data.js` 的 `src`，影院页会自动变成真播放页。

一个现实限制：`pan.baidu.com/pfile/video?path=…`（旧版是 `play/video#/video?path=`，会报「视频加载失败」）是按「文件在你自己的网盘里」这个前提工作的。
**别人打开你的 GitHub Pages 点不出片**，只有你自己的浏览器（已登录同一账号）能播。
要给外人看，必须走直链。

## 支持的操作

| 操作 | 效果 |
|---|---|
| 鼠标停在某张牌上 | 抽出来、扶正，两边让开 |
| 点牌 | 进目录 / 开视频（触屏第一下翻开、第二下进入） |
| ← → / 滚轮 | 换一张停留的牌 |
| 搜索框 | 按片名或目录名过滤 |
| `Esc` | 关播放器；再按一次回目录 |
| 空格 | 播放暂停 |
| 双击画面 | 全屏 |

深链：`#/body` 直接进目录，`#/body/3` 直接播第 3 集。

## 部署到 GitHub Pages

```bash
git init
git add .
git commit -m "init: 斑马放映室"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后到仓库 **Settings → Pages**，Source 选 `Deploy from a branch`，
分支选 `main` / 目录选 `/ (root)`，保存。等一两分钟，
地址是 `https://<用户名>.github.io/<仓库名>/`。

`.nojekyll` 已经放好了，避免 GitHub 用 Jekyll 处理静态资源。

## 已知边界

- 缩略图是抓下来存在本地的，网盘那边换了封面要重跑同步脚本。
- 页面本身不存视频，所有片源都是运行时从 `src` 加载。
- 直链会过期（几天到几个月），长期用建议把 mp4 放对象存储。
- 片源服务器没开 CORS 或禁止 `<video>` 跨域，浏览器会直接报错，前端绕不过去。
- 扇形是纯 CSS transform；120 张缩略图用了 `loading="lazy"`，一屏只加载可见的几张。
